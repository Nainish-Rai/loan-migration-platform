# Testing

Tests are the outermost ring: they depend on the code, and nothing depends on them.

| Layer            | Tests                                                                                            | Uses                                                                                     | Budget              |
| ---------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- | ------------------- |
| Domain           | Rules and invariants, e.g. a grant never outlives 300 s, a spec version never changes            | plain Vitest, fast-check for properties                                                  | < 2 s per service   |
| Application      | Each use case with in-memory port fakes, e.g. `decide-action` denies when the ledger fake throws | Vitest                                                                                   | < 5 s per service   |
| Adapters         | Each adapter against the real thing                                                              | Testcontainers: Postgres, Kafka, Neo4j, an S3-compatible store with Object Lock, OpenBao | minutes, run in CI  |
| Contracts        | Breaking-change checks on protobuf and events; consumer tests on activity interfaces             | `buf breaking`, AsyncAPI diff                                                            | every PR            |
| Policies         | One case per rule: request + expected decision                                                   | Cedar test cases in `policies/tests`                                                     | every PR            |
| Chaos            | Ledger down, OpenBao slow, model gateway gone: assert deny or pause, never allow                 | Toxiproxy                                                                                | nightly             |
| Characterization | Replay legacy decisions on landed data and pin today's outputs before anything changes           | replay harness, `jobs/verify/l4_replay_decisions.py`                                     | per run             |
| Tracer bullet    | One 2020 born-digital application through every service, on staging                              | `tests/e2e/tracer-bullet`                                                                | every merge to main |

## The tracer bullet

The first thing built, and kept as production code: one application lands, is masked, extracted, linked in the graph, mapped (one field: `applicant.monthly_income`), allowed by the gate and recorded in the ledger, compiled to Spark, loaded into a staging copy, checked L0–L4, and opened as a merge request. If that path works, the boundaries hold.

## Fixtures

Synthetic loan files only, generated by `packages/testing`. Real customer data never enters a test, a fixture or a log.
